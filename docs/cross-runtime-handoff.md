# CLI 与 WebApp 一致性及本次交接

## 当前结构与约定

- CLI：命令行转换；共用核心为 `src/render.mjs`、配置及其依赖。
- WebApp：服务端部署与静态部署共用 `web/` 界面；主屏模式是打开方式，均使用部署首页，不另设 `/app/`。
- `src/web-input.mjs`、`src/web-document.mjs`：共用输入／有效配置处理与预览准备。
- `web/runtime-request.mjs`：界面的请求边界；静态专用能力在 `web/platform-static/`，不在界面中复制排版规则。
- `src/static-build.mjs`：唯一静态构建函数；启动命令与构建脚本均调用它。输出 `dist/static/`，不可手改，不进入 Git。
- 产品版本仅来自 `package.json`，通过 `src/version.mjs` 读取；CLI 与页面底栏统一显示。页面版本详情提供部署方式和提交号。
- 历史 `offline/`、原型构建入口、原型说明和导入兼容逻辑已移除。已有测试网站数据不自动清除，需要的草稿先下载备份。

详细使用见 [WebApp](webapp.md)、[静态部署](static-webapp.md)。

## 自动检查入口

在需要验收的工作树根目录执行：

```bash
npm run check:consistency
```

该命令先重新构建静态网站，再用 general、paper、gb、skill 四类共用示例核对：

- 真实 CLI `--html-only` 输出与共用排版核心。
- 已构建浏览器核心与 Node 核心的分页 HTML、打印配置。
- 真实临时 Node HTTP API 与静态适配器的预览 HTML、有效配置和控件策略。
- CLI、Node API、静态产物的产品版本与提交号；非法配置的状态与诊断。

仅归一化资源根路径、生成时间及 CLI/Web 等价的 `&amp;` 序列化，不忽略正文、编号或版式差异。失败输出首处差异；临时监听与临时 CLI 文件在结束后清理，静态构建产物保留。需要本机监听权限，不下载依赖或资源。

此检查在 Node 中执行静态模块，并不模拟真实浏览器，也不声称覆盖 CLI 独有的本地资源／扩展配置。已有配置、编辑器、服务端测试仍按修改范围选择执行；本入口不替代全部现有测试。

## 人工验收与发布

1. 从同一提交分别启动 `./bin/md2pdf webapp --port 8771` 和 `./bin/md2pdf webapp --static --port 8770`，核对底栏版本与提交号。
2. 用同一 Markdown 和有效配置，对照两种 WebApp 的编辑、打开／创建、草稿、模板库、助手、缩放、全屏、同步定位及大纲。
3. 用 CLI、服务端和静态打印生成真实 PDF，检查页数、中文检索、公式、图表、长表格、目录、页眉页脚和书签。静态版本通过浏览器打印保存，暂不提供大纲补全；字体、打印环境及 iPhone 输出仍需单独验收。
4. 缓存就绪后停服重开、编辑和下载 Markdown；静态部署另验收本地预览及直接打印。更新资源后检查保存后更新和其他旧窗口继续使用。
5. 发布前确认工作区干净、产品版本与目标 tag 一致，从同一提交生成安装包和静态网站；分别验收 Pages 仓库子路径和自定义域名。没有完成的项目应明确记录，不能用自动检查通过代替。

当前批准的平台差异：服务端／CLI 使用 Chrome 导出；静态部署使用浏览器打印保存 PDF，暂不保证书签大纲；DOI 需要联网且静态查询受上游跨域策略限制。配置含义、正文结构、编号、引用与主题规则必须共用，不应因平台悄悄变化。

## CNB 版本校验修复（2026-10-17）

版本来源统一后，旧 `tests/checks.mjs` 仍搜索硬编码 VERSION，导致未破坏副本失败。现改为运行共享版本模块及 CLI，并与 `package.json` 比较。守卫自测由 `tests/guard-selftest.mjs` 执行：基线必须通过，每例从干净副本开始，确认实际修改及指定断言失败；版本破坏改为让共享模块返回错误版本，不再修改唯一版本来源制造假不一致。

本地验收：`bash scripts/validate.sh`（包含基线和六个破坏用例）、`node --test tests/webapp-command-checks.mjs`、`npm run check:consistency`。另验证了只改 package 版本正常通过、基线失败立即停止。线上 CNB 日志无法直接读取，远端流水线须在获得推送授权后另行确认；本修复不改渲染、服务、tag 或其他工作树。
