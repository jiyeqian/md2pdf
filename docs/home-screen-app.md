# WebApp 使用说明

## 一个入口，两种打开方式

WebApp 可以在浏览器中打开，也可以添加到主屏幕，以独立窗口使用。两种方式共用界面、草稿保存逻辑、安装资源和更新机制；主屏模式不是独立产品或版本。

每个部署只使用一个固定入口：服务端部署使用根地址 `/`，静态部署使用其发布目录。没有单独的 `/app/` 入口。服务端和静态部署的能力区别见 [静态部署 WebApp](offline-web.md)。

- 服务端部署：首次联网准备后支持离线启动、编辑、草稿恢复和 Markdown 下载；排版预览、PDF 导出和 DOI 查询需要联网及服务可用。
- 静态部署：资源准备后支持离线编辑、排版和 PDF 导出；DOI 查询仍需要联网。
- 添加到主屏幕后适配安全区、键盘视口与后台恢复；支持系统文件分享时提供分享操作，否则使用下载。

## 服务端启动与访问

在本工作树启动：

```bash
cd /Users/jiyeqian/.codex/worktrees/6654/md2pdf
./bin/md2pdf webapp --port 8765
```

也可以直接使用已安装的 `md2pdf webapp --port 8765`。电脑访问 <http://127.0.0.1:8765/>。如继续使用已配置的 Caddy 代理，手机访问 <https://web.mbp16.qianjiye.de:8443/>，浏览器和主屏图标均使用这个根地址。

可信 HTTPS 或电脑 localhost 才能准备离线缓存。局域网 HTTP 可以在线使用，但不能准备离线启动资源。

局域网直接访问时，用电脑当前私有 IPv4 地址启动：

```bash
MD2PDF_LAN_HOST=192.168.1.9 PORT=3116 node src/server.mjs
```

手机访问 `http://192.168.1.9:3116/`。未设置时默认仅监听本机；不能与 `MD2PDF_PUBLIC_HOST` 同时启用。电脑需保持服务运行并允许端口入站访问。

## 安装、离线与更新

1. 联网打开固定入口，等待“离线编辑已就绪”（静态部署为“完整离线资源已就绪”）。浏览器和主屏模式自动使用各自部署的缓存机制。
2. 如需独立窗口，在浏览器分享菜单选择“添加到主屏幕”。首次从图标打开时保持联网，再确认资源已就绪。
3. 断网后可以通过同一地址或主屏图标重新打开。编辑后确认“草稿已保存到此浏览器”，重要文档及时下载 Markdown 备份。
4. 出现新版提示时，点击“保存草稿并更新”。保存失败保留当前页面；未更新的窗口继续使用其原版本资源。

缓存只保存界面资源和公开配置、模板；用户正文保存在 IndexedDB，渲染请求和导出结果不进入服务端 WebApp 的离线缓存。桌面浏览器也使用相同的资源缓存与更新机制，服务端排版及 PDF 导出流程不变。

草稿按浏览器及来源隔离，不自动跨设备同步。协议、端口、域名变化会形成不同存储；系统也可能隔离浏览器与主屏窗口的存储。清理网站数据或系统回收存储可能删除缓存和草稿，需要联网重新准备并从下载备份恢复。

本项目尚未发布，不提供旧 `/app/` 测试入口迁移。旧测试图标可删除后从根地址重新添加；旧测试缓存可以在浏览器网站数据设置中清理。清理前先下载需要保留的草稿。

## 验收

- 桌面浏览器：打开、创建、草稿切换、缩放、全屏、模板库、预览和下载。
- 主屏模式：检查独立窗口、安全区、键盘弹出、快捷菜单、后台返回、文件下载及系统分享。
- 缓存就绪后停止服务或断网，刷新根地址，检查草稿恢复与 Markdown 下载；服务端部署恢复连接后检查预览。
- 更新资源后检查提示、保存后更新，以及其他旧窗口继续编辑。

静态部署的构建、PDF 大纲和 GitHub Pages 使用方法见 [静态部署 WebApp](offline-web.md)。手机系统分享与打印仍需实体设备验收。
