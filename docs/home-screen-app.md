# 主屏幕 App

## 本期能力

- Manifest、独立启动、主屏图标和 Apple 图标。
- 主屏模式的状态栏、底部手势区、横屏安全区及键盘视口适配；普通浏览器保持原布局。
- 恢复最近草稿与排版配置，后台返回后重新测量编辑器和工作区。
- 支持系统文件分享时，Markdown 和 PDF 生成后提供“下载文件／分享…”；不支持时直接沿用下载。
- 临时断网可继续编辑和保存当前已打开的文档；预览、PDF 导出和首次加载需要服务在线。

本期没有 Service Worker 和离线启动缓存。服务端的渲染与 PDF 导出链路保持不变。

## 局域网启动

在该工作树运行，替换为电脑当前私有 IPv4 地址：

```bash
cd /Users/jiyeqian/.codex/worktrees/6654/md2pdf
MD2PDF_LAN_HOST=192.168.1.9 PORT=3116 node src/server.mjs
```

电脑浏览器可使用 `http://127.0.0.1:3116/`；同一局域网手机访问 `http://192.168.1.9:3116/`。电脑需保持唤醒、服务运行，并允许该端口入站访问。

未设置 `MD2PDF_LAN_HOST` 时仍默认仅监听本机。局域网模式仅接受配置 IP 与回环地址的 Host/Origin，不使用公网代理模式，也不能与 `MD2PDF_PUBLIC_HOST` 同时启用。

IP、端口、协议或浏览器变化会形成不同的草稿存储空间；验收时固定使用同一地址，重要内容先下载备份。

## iPhone 验收

1. 在 Safari 打开局域网地址，编辑文档，确认右下角提示草稿已保存。
2. 从分享菜单选择“添加到主屏幕”；系统提供“作为网页 App 打开”选项时保持开启。
3. 从主屏图标打开，检查名称、图标、独立窗口、安全区、模板菜单和文档恢复。首次进入主屏 App 可能使用独立存储，不应假定浏览器里的旧草稿必然共享；可打开先前下载的 Markdown，随后在 App 内验收恢复。
4. 打开键盘，输入 `/b`、`/r`；滚动页面及编辑器、切换横竖屏，检查菜单跟随光标，全屏时底部工具不被键盘遮挡。
5. 编辑并等待保存，切到其他 App 再返回；退出后重新从主屏打开，检查正文与排版配置。
6. 下载 Markdown 和 PDF，检查文件内容、文件名以及文件 App 中的可用性。
7. 临时断网继续修改草稿；联网后恢复预览。不要在断网时刷新或关闭后尝试离线冷启动。
8. 在普通桌面浏览器检查打开／创建、草稿切换、缩放、全屏、预览及下载行为。

iOS 26 允许网站添加到主屏幕后作为 Web App 打开，相关行为见 [WebKit 说明](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/)。其他系统的安装能力取决于系统和浏览器。

系统文件分享依赖 HTTPS 安全上下文和浏览器支持，见 [Web Share API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Share_API)。局域网 HTTP 主要验收主屏布局、编辑、恢复及下载；系统分享需在可信 HTTPS 地址另行真机验收，不会通过关闭浏览器安全限制来启用。

## 自动检查

```bash
npm run test:app-shell
```

覆盖局域网 Host/Origin 限制、Manifest/PNG 图标、普通桌面布局与无主屏壳基线的一致性、主屏恢复、缩短视口、后台返回、Markdown/PDF 文件操作、临时断网保存及 HTTP 下的草稿标识兼容。系统分享使用浏览器接口替身，不能代替实体 iPhone 的系统面板验收。
