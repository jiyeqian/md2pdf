# 离线排版原型记录与 PDF 大纲说明

正式界面已整合为 [静态离线 Web](offline-web.md)。以下保留技术验证记录和 PDF 大纲规则；原型地址不再作为正式版本验收入口。

## 当前定位

独立验证浏览器本地排版及静态部署的可行性，尚非完整离线版的正式交付。现有 CLI、桌面 WebApp、8765 服务及其下载流程没有接入此原型。

- 从当前 `src/render.mjs` 及其配置、编号、主题源码生成浏览器模块，不维护第二套 Markdown 排版规则。
- YAML 解析和语法高亮使用仓库现有版本；构建时适配 Node 的文件、路径、环境与模块接口，原文件保持不变。
- 公式、Mermaid、分页、主题、示例均随静态目录分发，没有 CDN 或排版 API 请求。
- 使用相对资源路径和目录范围的 Service Worker，支持站点根目录或 GitHub Pages 仓库子路径。
- 原型草稿使用独立的 IndexedDB 数据库，不覆盖正式应用的草稿。

## 构建与打开

在 mobile 工作树执行：

```bash
cd /Users/jiyeqian/.codex/worktrees/6654/md2pdf
node scripts/build-offline.mjs
python3 -m http.server 8770 --bind 127.0.0.1 --directory dist
```

电脑打开 <http://127.0.0.1:8770/offline/>。首次需要静态服务提供资源；等待“完整离线资源已就绪”后，可以停止静态服务，再刷新并更新预览。

构建输出位于 `dist/offline/`，已被 Git 忽略；重建会更新生成文件。输出中的 `build-info.json` 记录资源大小与版本，当前约 6.3 MB（未压缩，含 PDF 大纲处理库），不包含跨平台中文字体包。不要把输出目录当作源文件修改。

127.0.0.1 入口仅供当前电脑使用。手机离线启动需要将该静态目录映射到可信 HTTPS 地址，或部署到 GitHub Pages；服务端 WebApp 使用根入口 `/`；正式静态部署见 [静态 WebApp](offline-web.md)。

## 验收步骤

1. 等待“完整离线资源已就绪”和“离线排版完成”，确认公式、图表与中文。
2. 依次载入通用文档、学术论文、国家标准、技能文档和长表格样例，检查标题、目录、跨页表格、页码及附录。
3. 停止静态服务，重新打开完整入口，编辑后点击“更新离线预览”，确认仍可完成排版。
4. 点击“① 打印／另存为 PDF”，在系统打印面板完整保存当前文档；使用预览的纸张尺寸与方向、缩放 100%，关闭浏览器附加页眉页脚，按需要启用背景图形。
5. 点击“② 选择 PDF 并补全大纲…”，选择刚保存的 PDF，浏览器本地写入标题书签并下载 `原文件名-含大纲.pdf`。检查 PDF 阅读器的书签侧栏、中文标题、层级、目标页和跳转位置。原文件不会被覆盖。
6. 用正式版处理同一 Markdown 和有效配置，对照 PDF 页数、分页、中文检索与复制、公式、图表、目录和页眉页脚。原型界面没有完整配置工具条，可通过 Markdown frontmatter 提供配置。
7. iPhone 上验证主屏启动、打印／分享保存路径、长文档耗时和内存。首次离线准备必须在主屏 App 自身完成，不能假定浏览器与主屏共享缓存。

新版资源完整下载并校验后，新导航会读取新版；已打开窗口保留原版本资源，不强制刷新。出现“新版已就绪”时，点击“保存草稿并更新”；保存失败保留页面。无需关闭所有窗口或清除网站数据。旧缓存协议首次迁移时，联网刷新以下载新版，等待片刻后再刷新一次即可进入新版。更新前仍建议下载重要 Markdown 备份。清理网站数据会影响离线资源和原型草稿。

## PDF 与性能边界

当前采用 [浏览器系统打印](https://developer.mozilla.org/en-US/docs/Web/API/Window/print)，随后在浏览器中为刚保存的 PDF 补全 Outline 并下载新文件；仍是两步操作，并非一键生成 PDF。浏览器设置、设备字体和打印实现可能造成与正式版 Chrome 导出的差异；验证通过前，不能认定两端 PDF 一致。

正式版会根据文档与配置选用 Chrome 直接打印或 Paged.js；原型统一提供分页预览并打印该预览。因此“渲染核心输出一致”不代表所有导出分页一致。这是需要比较验证的候选路线，尚未替换正式版行为。

当前不打包中文字体，使用正式主题中的系统字体回退；跨设备字体一致性、字体包下载量和 iPhone 内存仍是进入正式实现前的决策项。原型在点击时排版，避免每次输入都重新运行公式、图表和分页。

## 桌面 PDF 大纲

- 分页完成时冻结当前预览的标题层级、实际页序与标题坐标；完成后为选择的 PDF 写入标准 `/Outlines` 书签树。PDF 页码使用实际页序，包括封面与目录，区别于页脚显示的罗马／阿拉伯编号。
- 支持中文标题及多级书签；文档配置 `outline: false` 时不启用补全按钮。
- 编辑正文或更新预览后，旧位置立即失效；更新预览后应重新打印与之对应的 PDF。补全过程若预览变化，会放弃下载该结果。
- 补全前检查 PDF 的页数、纸张尺寸和方向；不匹配则拒绝处理。页数和尺寸一致不等于文档内容一致，必须选择刚才打印的完整 PDF，不要选择其他文档或仅打印部分页码。
- PDF 与文档不上传服务器；不重新绘制、分页或栅格化页面。只写入书签及打开侧栏的设置，保留原页面内容流和文字。
- 补全使用固定版本 `pdf-lib` 1.17.1（MIT），随离线资源分发，运行时不依赖 CDN。源码与完整性摘要见 `vendor/pdf-lib/`。首次缓存约增加 0.53 MB，处理时才加载该模块。

## GitHub Pages 部署

GitHub Pages 只需托管生成的 HTML、CSS、JavaScript 和资源，见 [官方静态托管说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)。

- 本地构建后，将 `dist/offline/` 目录的**内容**作为 Pages 发布产物，包含 `.nojekyll`，入口为 `index.html`。
- 可通过项目现有 Pages 发布流程上传该目录；本次未配置自动发布、未推送或发布任何站点。
- 发布为项目站点时，入口为 `https://<用户名>.github.io/<仓库名>/`；如发布到子目录，使用该子目录的完整末尾 `/` 地址。
- 所有资源相对当前目录解析，无须把路径写死为 `/` 或 `/md2pdf/`。这里的 `/md2pdf/` 仅是构建适配器内部的虚拟路径，不是部署路径。
- 部署更新必须一次提供完整构建产物；资源内容与缓存清单不一致时，新缓存安装会失败，保留原有版本。
