# 约束驱动的版面校准系统：设计讨论记录

## 状态与范围

记录日期：2026-10-28。本文保存已讨论的方案，作为后续统一分步骤实施的依据；具体格式、接口和阶段边界仍可继续讨论。本文不代表工具已经实现，也不构成开始实施的授权。

优先完成 GB/T 系列国家标准封面，其次是 GB；GB/Z 暂不考虑。封面试点稳定后，再考虑正文首页、目次、附录等版面及其他软件的复用。

## 目标与方法

输入全部文字、字体和定义的空间关系，求解排版参数；通过实际排版引擎生成 PDF，独立测量空间关系，再在允许范围内迭代优化，直至各项必需约束满足验收条件。

采用约束求解与数值优化作为核心，机器学习辅助识别样本。初期不训练“文字直接生成 CSS”的模型。

| 工作 | 方法 |
| --- | --- |
| 固定坐标、尺寸、对齐和间距 | 几何约束求解 |
| 渲染结果与目标之间的剩余偏差 | 有界数值优化 |
| 最终输出测量 | PDF 矢量分析与栅格墨迹交叉验证 |
| 扫描封面的文字、横线与标志识别 | OCR、图像识别，可采用机器学习 |
| 换行选择 | 初期采用规则与候选搜索，后续再评估学习方法 |

有界非线性最小二乘是候选方法之一，参见 [SciPy 官方文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.least_squares.html)。这不是新增依赖的决定，实际实现应优先复用项目现有能力。

## 统一版式定义

以机器可读的 JSON 为单一维护来源，生成 Markdown 台账、标注图及检查项。测量结果单独保存，不覆盖目标值。具体 schema 后续设计。

定义至少包含：

- 来源：标准号、版本、图号、原件哈希。
- 元素：文字、标志、横线、稳定标识及可选条件。
- 字体：指定字体、字号、字形资源及其哈希。
- 几何关系：坐标、尺寸、间距、对齐、边界和不得重叠。
- 测量端点：墨迹边缘、图形边缘、基线和行框，明确区分。
- 约束级别：规范明确要求、推导关系、工程选择。
- 验收规则：容差、测量方法、不确定度及缺项处理。

例如，保存“英文名称上缘＝中文名称最后一行墨迹下缘＋10 mm”的关系，不保存某个范例的英文名称固定纵坐标。

已有基础：[图 E.5 尺寸台账](gb-cover-e5-ledger.md)、[JSON 台账](../tests/fixtures/gb-cover-e5.json)、[校准记录](gb-cover-e5-calibration.md)。这些现有专项文件尚不等于通用版式定义或通用自动优化工具。

## 校准工作流

1. 检查约束完整性和可行性，识别定位不足、相互矛盾、内容无法容纳等情况。
2. 按指定字体求解初始布局，固定元素直接计算，可变文字生成候选换行与位置。
3. 通过 md2pdf 共用渲染能力输出 PDF，覆盖 CLI、服务端和静态共用打印 HTML。
4. 独立测量最终输出，优先分析矢量线条与实际字形轮廓，以栅格墨迹交叉验证；不得以字体度量框代替可见字形边缘。
5. 仅调整允许变化的参数，优先选择换行方案，再优化连续位置参数，避免盲目搜索全部 CSS 属性。
6. 逐项验收，保存目标、实测、误差、状态、输入和输出哈希、字体及渲染环境。

规定字号、文字比例和标志比例不能为满足位置约束而随意改变。允许调整的定位修正量、字间距或换行范围应由版式定义明确声明。

停止条件是每项必需约束均满足验收条件，不能只看平均误差下降。约束不可行、测量不可信或迭代停滞时，应输出原因并停止，不自动放宽阈值，不无限迭代。可选元素缺失时相关检查标为不适用，不计为通过。

## 样本使用与验证顺序

用户提供的样本目录：`~/Desktop/GB/Covers`。讨论时只核对了文件清单，尚未逐份测量。

1. GB/T：覆盖长短中文名称、多行英文、有无代替编号、采标信息和不同机构行数。
2. GB：复用共用几何规则，单独确认类别差异。
3. GB/Z：暂缓。

规范正文及附图作为目标依据；收集的封面用于发现遗漏与验证泛化能力。旧版样本，尤其早于 GB/T 1.1—2020 的样本，不直接作为新版规范的合格答案。先检查样本版本、原始幅面、扫描或矢量属性及适用规则，再决定用途。

部分样本保留为独立验证集，不参与参数校准；同时保留图示占位文字和实际范例，避免只拟合已见文字。

## 工具组织与拟议接口

先在 md2pdf 中实现开发者使用的工具，核心接口保持可拆分。存在实际跨项目复用需求后，再评估独立工具。

以下只是拟议能力名称，并非已可执行命令：

| 能力 | 用途 |
| --- | --- |
| `layout inspect` | 测量 PDF，导出元素位置与空间关系 |
| `layout validate` | 对照版式定义逐项验收 |
| `layout calibrate` | 在允许范围内求解和迭代 |
| `layout report` | 生成误差表、尺寸标注图及重叠检查图 |

优化过程用于开发、校准和回归验收阶段。用户正常打开模板时使用已经确认的规则，不必每次运行优化器；内容变化仍由确定性的排版规则处理。CLI 与 WebApp 共用规则，不复制业务逻辑。

## 精度与验收边界

目标是达到类似 CAD 的毫米坐标、几何约束、尺寸标注与可重复验收能力，精度声明必须包含字体、渲染器版本和测量不确定度。

600 dpi 下一个像素约为 0.042 mm；数值相同不等于没有测量误差。既有专项校准采用的 ±0.2 mm 是工程阈值，不是标准规定的容差。后续按约束类型和测量能力确定阈值，不以测试结果反向放宽要求。

CSS 物理长度单位不替代最终 PDF 测量；屏幕大小不能证明实际打印尺寸，参见 [W3C 长度单位规范](https://www.w3.org/TR/css-values/#absolute-lengths)。静态系统打印对话框、实体打印机及专用字资源确认应单独验收。
