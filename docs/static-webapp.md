# 静态部署 WebApp

## 一套源码、两个运行环境

正式静态版直接构建 `web/` 中的在线 Web 界面，不再维护原型编辑器。在线页面仍默认调用 Node.js 服务；只有静态构建注入 `web/platform-static/boot.js`，将界面的请求交给浏览器适配器。

| 内容 | 共用源码 | 静态构建的处理 |
| --- | --- | --- |
| 编辑器、工具栏、助手、缩放、全屏、同步定位 | `web/` | 自动复制界面与资源，不另写组件 |
| 本地草稿、打开／创建、模板菜单 | `web/` | 使用相同的 IndexedDB 保存与恢复逻辑 |
| 排版、配置、主题、编号、引用 | `src/render.mjs` 及依赖 | 替换 Node 文件／路径接口，自动收集模块依赖 |
| 输入校验、有效配置、可调选项限制 | `src/web-input.mjs`、`src/web-options.mjs` | 浏览器与 Node 接口调用同一函数 |
| 预览增强、同步定位与大纲消息 | `src/web-document.mjs`、`src/preview.mjs` | 同样内嵌排版资源并保持预览 sandbox |
| 示例目录及内容 | `src/web-examples.mjs` | 构建时生成本地数据，自动继承目录变化 |
| DOI 解析与 BibTeX 转换 | `src/doi.mjs` | 用户主动查询时直连相同公开上游，需网络与上游 CORS 支持 |
| PDF | 同一排版核心与配置 | 在线版仍由 Chrome 一键导出；静态版打印后本地补全大纲 |

维护界面或排版规则时修改原有源码，再重建即可。只有浏览器与 Node 能力不同的文件操作、PDF 与缓存更新保留适配代码；不复制业务规则。首发仍以桌面浏览器为主，iPhone PDF 排版继续单独验收。

## 构建与验收入口

```bash
cd /Users/jiyeqian/.codex/worktrees/6654/md2pdf
./bin/md2pdf webapp --static --port 8770
```

打开 <http://127.0.0.1:8770/>。8770 已运行时无需重复启动；重建后等待新版资源就绪，点击“保存草稿并更新”。本次不需要启动 8765，也不更改它的运行状态。

输出为 `dist/static/`，当前约 8.3 MB（未压缩，含完整编辑器、公式、图表、分页及 PDF 大纲库）。构建不请求网络或 CDN，输出不包含用户文档。

启动时总是先构建当前程序所在目录的源码，成功后才提供网页；失败不会启动旧产物。构建写入临时目录，成功后替换正式目录。修改源码后重新启动，页面出现新版提示时保存后更新。目录不取决于当前终端位置。

只生成发布产物、不启动服务时使用 `node scripts/build-static.mjs`。两种入口调用同一个构建函数。源码 `web/platform-static/` 只包含静态平台适配；产物 `dist/static/` 包含共用界面、核心和完整资源，不手工修改。

## 使用与差异

- 首次联网打开，等待“完整离线资源已就绪”。以后可以停服／断网后重新打开、编辑、排版、保存草稿及下载 Markdown。
- 使用原工具栏的打开、模板创建、草稿列表、专业助手、搜索、图表、公式、排版选项和全屏等操作。
- 点击原“下载 PDF”按钮，进入本地导出窗口；完整打印保存 PDF，再选择该 PDF 下载含大纲版本。使用文档纸张、100% 缩放，关闭浏览器附加页眉页脚。详细规则见下方 PDF 大纲说明。
- DOI 查询需网络，仅在用户主动查询时请求公开上游；网络或跨域限制导致失败时，可以使用原有的手动 BibTeX 入口。PDF 和正文不上传。
- 草稿按浏览器及来源隔离。不同协议、端口、域名与主屏模式可能有独立存储；更换入口前下载 Markdown 备份。清理网站数据可能同时删除草稿与缓存。

## GitHub Pages 与域名

将 `dist/static/` 目录的**内容**作为 Pages 发布产物（保留 `.nojekyll`），即可用于：

- `https://jiyeqian.github.io/md2pdf/`
- 绑定域名后的 `https://md2pdf.qianjiye.de/`

构建自动处理资源路径与 Manifest，页面导航和缓存范围以当前部署目录为准；两种地址使用同一份构建产物。这里没有添加自动发布或改变 DNS/CNAME，实际发布仍需单独执行。

## 验收清单

1. 对照在线界面检查工具栏、模板库、专业助手、预览大纲、配置、缩放、全屏与同步定位。
2. 打开文件、创建空文件及模板文档，切换、删除、恢复草稿，下载 Markdown。
3. 用同一文档与有效配置对照在线预览，尤其是中文、公式、Mermaid、长表格、目录及 GB 附录。
4. 等缓存就绪后停止 8770，刷新、重新排版，并通过正式 PDF 导出窗口补全大纲。
5. 重建后保留旧窗口，确认其他新窗口可进入新版；保存后更新不丢草稿。
6. 在实际 Pages 仓库子路径和自定义域名分别检查图标、模板图片、模块加载与离线重开。

已核对四类文档的 Node API 与静态适配器：预览 HTML（除生成时间）、有效配置及控件策略一致；非法配置返回的状态、字段与行号诊断一致。真实手机 PDF 及正式公网部署仍需单独验收。

## PDF 大纲与平台边界

PDF 使用浏览器系统打印，随后选择刚保存的 PDF，在本地补全大纲。当前是两步操作；浏览器字体、打印设置可能造成与服务端 Chrome 导出的差异，iPhone 输出仍需真机验收。

- 导出窗口完成分页后记录标题层级、实际页序与坐标，支持中文及多级书签；`outline: false` 禁用补全。
- 必须选择与当前导出窗口对应的完整 PDF。检查页数、纸张尺寸和方向，不匹配时拒绝处理；这些检查不能证明文档内容相同。
- 使用文档纸张、100% 缩放，关闭浏览器附加页眉页脚。正文变化后重新打开导出窗口并重新打印。
- 补全不上传 PDF、不重绘页面，只写入书签及打开侧栏设置；原始文件不覆盖。
- 随静态资源分发固定版本 pdf-lib，处理时加载，无需 CDN。字体使用主题的系统字体回退，不打包中文字体。
